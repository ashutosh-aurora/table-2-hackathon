# Deeper questions (optional)

Optional prompts for a table that wants more rigour — to think harder from problem to solution to
delivery. **The day's loop runs fine without these.** Pull from them when a team is stuck or wants to go
deeper at a step; don't run them as a checklist.

## Value — problem loop / deepen
- Have we captured all the end-user needs that matter *to them*? What's been missed?
- Would this actually deliver the value we expect — and how would we know?

## Shaping rigour — solution loop
- Do the requirements reflect *actual* user / market needs, or our assumptions?
- What's the approach — and what does it depend on (data, inputs)? What are the implications?
- Is the terminology and who-owns-what clear, or a likely source of confusion?
  (see `definitions/glossary.md` and `definitions/convention-gaps.md`)
- What open questions must close before we'd commit to building this for real?

## All the way to delivery — stretch
- What interface contracts would cross teams? (see `context/team-topology/`)
- What tests would prove it works?
- Who would own it, and who needs to be told?

## Reflection — retro
- How would we improve the way we worked today?
