# Worked example — Seamless PPA journey for a hybrid solar asset

A complete, co-produced pass through the **core shape** (frame → slice → prototype) on a real problem
from Donna's domain: today a client modelling a PPA for a hybrid solar asset re-enters the same asset
across three Aurora EOS products (Solaris → Chronos → Lumus), with lossy or manual hand-offs between
them. The mock shows the coherent journey it could be, built to start a team conversation.

The full journey now wraps this core with `plan-the-session`, the problem loop, deepen, and a retro
(see `CLAUDE.md`); this example focuses on the framing → slice → prototype middle.

It was produced by walking the kit with Donna, not fabricated. The product screenshots it was grounded
in are kept local (gitignored); `00-current-state.md` describes them in words so this stands alone.

## Read in order

- `00-current-state.md` — what today's three-product journey looks like
- `01-team-context.md` — context the team authored
- `02-frame.md` — the framed problem, including the three real breaks
- `03-slice.md` — the one slice chosen
- `04-prototype/seamless-journey.html` — the mock (open in a browser; works offline). Three screens,
  inherited fields highlighted, current breaks annotated.

## Using this as the facilitator example

This sits squarely in the product domain, so if used as the facilitator-facing example it could anchor
tables onto PPA. It mainly serves as Donna's real test that the loop works end to end. Pick a more
neutral example for facilitator training if anchoring is a concern.
