# Worked example — Seamless PPA journey for a hybrid solar asset

A complete, co-produced pass through the five stages on a real problem from Donna's domain: today a
client modelling a PPA for a hybrid solar asset re-enters the same asset across three Aurora EOS
products (Solaris → Chronos → Lumus), with lossy or manual hand-offs between them. The prototype is a
throwaway mock of the coherent journey it could be, built to start a team conversation.

This example was produced by walking the kit's arc with Donna, not fabricated, and it grounds each
stage in the current-state captures in `current-state/` (which are gitignored, so the real product
screenshots stay local and unpublished).

## Read in order

1. `01-team-context.md` — context the team authored (stage 2)
2. `02-frame.md` — the framed problem, including the three real breaks (stage 3)
3. `03-slice.md` — the one slice chosen (stage 4)
4. `04-prototype/seamless-journey.html` — the throwaway mock (stage 5). Open it in a browser; it works
   offline. Three screens, with inherited fields highlighted and the current breaks annotated.

## A note on using this as the facilitator example

Unlike a deliberately off-theme example, this one sits squarely in the product domain, so if it were
the facilitator-facing worked example it could anchor tables onto PPA. It primarily serves here as
Donna's real test that the smallest end-to-end loop works. Pick a more neutral example for facilitator
training if anchoring is a concern.
